# minecraft-pack-1201

Приватная сборка Minecraft **1.20.1 / Forge 47.4.10** — 215 модов, формата [packwiz](https://packwiz.infra.link/).

## ⬇️ Скачать и играть (Windows)

**[▸ Скачать Minecraft-Pack-1.20.1.zip](https://github.com/CrystalysGolem/minecraft-pack-1201/raw/main/dist/Minecraft-Pack-1.20.1.zip)** — ссылка начинает скачивание сразу (≈95 КБ, это инстанс-каркас; сами моды подтянутся при первом запуске).

Порядок действий:

| # | Что делать |
|---|---|
| 0 | Установить лаунчер **[PrismLauncher](https://prismlauncher.org/download/windows)** (обычный лаунчер Minecraft не подойдёт). Java ставить не нужно — PrismLauncher скачает её сам (Java 17). |
| 1 | Скачать архив по ссылке выше и **распаковать** в любое место. |
| 2 | PrismLauncher → **Add Instance → Import from zip** → указать папку `Minecraft Pack 1.20.1` из архива. |
| 3 | Нажать **Play**. Первый запуск долгий: качается ≈570 МБ модов, конфигов и шейдеров. |

Что нужно на ПК: Windows 10/11 (64-бит), ≈10 ГБ свободного места, желательно 8 ГБ оперативки.
Подробная инструкция для игроков лежит внутри архива — файл **`ПРОЧТИ-МЕНЯ.txt`**.

## Фиксы модов

Инородные правки держим отдельными файлами, которые видно и легко пересобрать
(лицензии модов проверяем):

| Фикс | Что исправлено | Почему так |
|---|---|---|
| `resourcepacks/mcwbetters-fix.zip` | 54 blockstate-файла `*_balcony`, `*_log_parapet`, `*_plank_parapet` у 18 пород из BetterNether/BetterEnd (убираем условия на свойства `north/east/south/west/style`, `facing`, которых у этих блоков нет) — было 108 ошибок `Unknown property ...` в логе | Мод продолжает обновляться через Modrinth, а фикс лежит отдельным ресурспаком: видно, что и зачем, и пересобирается одной командой `tools/make_fix_pack.py --from-log minecraft/logs/latest.log`. Патч самого jar'а был бы невидимым и «залипал» бы на старой версии |

Ресурспак-фикс включается в игре автоматически: скрипт обновления (`_packwiz_update.cmd`)
дописывает его в `options.txt` → `resourcePacks`, а новичкам он уже включён в `starter/options.txt`
(игра видит ресурспак только если он в списке). Операция идемпотентная и не трогает другие записи.

## Настройки владельца передаются принудительно (`settings/`)

Настройки, которые игра синхронизировать не может (или которые легко «залипают» у игрока),
едут отдельным набором `settings/`:

- `settings/files/**` — раскладка и видео (`options.txt`), **весь** `config/` (включая
  `config/emi.css`, `config/oculus.properties`, `config/embeddium-options.json`,
  `config/sodiumextras-client.toml`, `config/xaero/**`, настройки JEI), `defaultconfigs/`, `emi.json`;
- `settings/instance/instance.cfg.overrides` — настройки инстанса PrismLauncher (консоль, окно,
  глобальные датапаки и прочие переключатели);
- `settings/instance/patches/**` — JVM-патчи владельца.

Клиент **раскладывает набор ПОВЕРХ своих настроек** — один раз на версию набора
(маркер `.pack_settings`), затем не трогает. Меняешь настройки → публикуешь → у всех игроков
они применяются на следующем запуске.

**Память Java задаётся владельцем:** в наборе для друзей едут `MinMemAlloc=2048`,
`MaxMemAlloc=6144` (6 ГБ) и `OverrideMemory=true`. **Никогда не передаются:** пути и версии Java,
`JvmArgs` (в них у владельца его собственный абсолютный путь), имя/иконка/id инстанса, личные
счётчики и экспортные поля. Не едут также сейвы, `logs/`, `screenshots/`, `backups/`, `servers.dat`,
`usercache.json`, точки и карты Xaero (`xaero/` — это данные миров, а не настройки), кэши
(`config/inventory-particles`, `config/emi-accelerator`), закладки и история поиска JEI
(`config/jei/world/**`).

**Часть настроек лежит прямо в паке** — её получают даже те, у кого ещё старый скрипт (игра сама
прочитает их при запуске): `emi.json`, `config/emi.css`, `config/oculus.properties`,
`config/embeddium-options.json`, `config/sodiumextras-client.toml`, `config/xaero/**` (настройки карты
и миникарты: клиент, common, профили `default`, категории радара) и настройки JEI.

**`options.txt` (раскладка, видео, список ресурспаков) передаётся один раз.** В `index.toml` он помечен
`preserve = true`: установщик скачает его, только если файла у игрока ещё нет, и **никогда не перезапишет
существующий**. Для тех, у кого сборка уже стояла, твоя версия приезжает один раз через шаг `:settings`
(на версию набора настроек) — и всё, дальше игрок настраивает игру под себя, его правки не откатываются.
Флаг `preserve` можно выставить и любым другим файлам настроек — тогда они тоже будут выдаваться один раз.

Важно: убирать файл из `index.toml` для этого НЕЛЬЗЯ — установщик удаляет у игроков то, что исчезло из пака.

## Первый запуск у новичка (`starter/`)

Дополнение к набору: часть «визуальных» файлов выдаётся **один раз и только если у игрока такого
файла ещё нет** — так ничего не затирается у того, кто уже играл (список — `tools/starter_list.txt`,
прогресс — файл `.pack_starter`, версия набора — `starter/manifest.txt`).

## Обновление самих скриптов (стаб + доставляемая логика)

Доставить код игроку паком нельзя: `packwiz` умеет только раскладывать и удалять файлы **внутри
каталога игры**, а строку предзапуска (`PreLaunchCommand`) и скрипты уровнем выше пак не трогает
вообще (проверено: запись `../файл` в индексе установщик нейтрализует и пишет внутрь каталога игры).
Поэтому роли разделены:

| Файл | Кто обновляет | Что делает |
|---|---|---|
| `minecraft/_packwiz_update.cmd` | сам себя (`<имя>.new` из пака, метка `:selfupdate`) | **стаб**: находит Java, читает `bootstrap.txt`, синхронизирует пак, зовёт логику |
| `minecraft/_packwiz_run.cmd` | **пак** (обычный файл индекса) | **логика**: настройки владельца, фикс-паки — всё, что нужно менять |
| `Обновить сборку.cmd` (корень инстанса) | никто, и не нужно | тонкая обёртка: ставит `PL_PATIENT=1` и зовёт стаб |

Логику (`_packwiz_run.cmd`) можно менять как угодно: в момент синхронизации она **не запущена**,
поэтому установщик свободно перезаписывает её — правка доезжает до игроков со следующего запуска,
без zip и без действий с их стороны. Стаб трогать почти не придётся: он неизменяем по смыслу
(Java + указатель + установщик) и на всякий случай тоже умеет подменять себя через `.new`.
Единственное, что требует разовой переустановки `dist/Minecraft-Pack-1.20.1.zip`, — инстанс
со скриптом, выпущенным **до** появления шага `:selfupdate`: ему нечем применить прилетевший `.new`.

## Устойчивость к обрывам связи

- Загрузка идёт с повторами: инструкция — 1–3 попытки, установка пакета — 2–4 попытки с паузой.
- Повторы прекращаются, если источник вообще недоступен (ждём только когда хост отвечает) —
  запуск игры не задерживается: в режиме «интернета нет вообще» предзапуск выходит за ~35 секунд.
- Скачанное не теряется: следующий запуск продолжает с того же места (кэш установщика).
- Любой сбой = код 0 и запуск на текущих файлах, а не «игра не запускается».

## Как работают обновления

Перед каждым запуском игры сборка синхронизируется сама: докачиваются новые моды, удаляются убранные,
обновляются конфиги, датапаки, шейдеры. Ничего нажимать не нужно.

Отдельная кнопка **`Обновить сборку.cmd`** (в корне папки инстанса) делает то же самое,
не запуская игру — удобно на первом запуске, чтобы видеть прогресс. Она лишь зовёт стаб
в «терпеливом» режиме (больше попыток и таймаутов, чем у тихого предзапуска).

Клиент у игрока знает **только адрес «инструкции загрузки»** и берёт источники оттуда:

```
игрок ──► bootstrap.txt ──► pack=<адрес пака>  (первый доступный и используется)
```

| Файл | Адрес | Когда используется |
|---|---|---|
| `bootstrap.txt` (инструкция) | `http://26.26.205.227:8787/bootstrap.txt` | когда ПК владельца в сети |
| `bootstrap.txt` (инструкция) | `https://raw.githubusercontent.com/CrystalysGolem/minecraft-pack-1201/main/bootstrap.txt` | всегда, когда доступен GitHub |
| пак (источник №1) | `http://26.26.205.227:8787/pack.toml` | ПК владельца по Radmin — быстрее |
| пак (источник №2) | `https://raw.githubusercontent.com/CrystalysGolem/minecraft-pack-1201/main/pack.toml` | всегда доступен |

Смена хостинга, адресов или порядка источников = правка одного файла `bootstrap.txt`.
**Файлы у игроков при этом менять не нужно.** Если недоступны все источники — игра всё равно
запустится на текущих файлах (предзапуск всегда возвращает код 0, иначе PrismLauncher отменил бы запуск).

**Не синхронизируется (остаётся личным у каждого):** сейвы, логи, скриншоты, бэкапы, `options.txt`
(кейбинды и графика), карты и точки Xaero, избранное EMI, кэши.

## Владельцу: как обновить сборку

1. Меняй моды/конфиги в своём инстансе как обычно (в каталоге инстанса PrismLauncher —
   `Edit Instance → Folders`, либо `instances\1.20.1` внутри папки данных PrismLauncher).
2. Кнопка **`ОБНОВИТЬ-СБОРКУ.cmd`** в корне инстанса → пункт `1`
   (или вручную: `cd tools && C:\Python314\python.exe pack_publish.py --push`).
   Скрипт сопоставит jar'ы с Modrinth по SHA-1, перегенерирует `mods/*.pw.toml`, `index.toml`,
   `pack.toml`, `bootstrap.txt`, скопирует конфиги и сделает `git commit && git push`.
3. Пункт `2` той же кнопки — раздать пак друзьям со своего ПК по Radmin (быстрая раздача,
   пока окно открыто).
4. Пункт `4` — открыть `bootstrap.txt` для правки (адреса/порядок источников).

Проверка перед пушем: `C:\Python314\python.exe pack_validate.py --urls` — целостность и все ссылки.

## Формат `bootstrap.txt` (инструкция загрузки)

```toml
# строки-комментарии (#) игнорируются
format=1
pack=http://26.26.205.227:8787/pack.toml                  # источник №1 (приоритет выше)
pack=https://raw.githubusercontent.com/.../pack.toml      # источник №2
```

Клиент читает `pack=` по порядку сверху вниз и берёт первый доступный. Успешной загрузкой считается
файл, в котором есть хотя бы одна строка `pack=` (поэтому страница ошибки прокси за инструкцию не сойдёт).

## Лицензия и использование

- **Моды** принадлежат их авторам и распространяются по их лицензиям (скачиваются с CDN Modrinth).
- **Конфиги, датапак `origins_tweaks`/`no_origin_debuffs`, настройки и структура пака** — работа
  владельца сборки. Используй приватно; **перед повторной публикацией, перезаливом на другой
  хостинг или включением в свою публичную сборку — спроси владельца.**
- Сборка собрана для игры узким кругом (друзья, Radmin), публичного сервера с ней нет.

## Приватность и безопасность

Что сделано в этом репозитории:

- **Не публикуется личное:** сейвы, логи, `crash-reports`, скриншоты, бэкапы, `options.txt`
  (кейбинды/графика), карты и точки Xaero, избранное EMI, кэши, `servers.dat`, `usercache.json`.
- **Абсолютные пути с именем пользователя Windows** вырезаются, личные поля конфигов
  (например список адресов в `connectivity.json`) обнуляются.
- **Локальные бэкапы владельца** (`*.bak-*`, `*.old`, `*.disabled`) в пак не попадают.
- **Перед каждой публикацией** генератор пака (`tools/pack_publish.py` рядом с инстансом владельца)
  сканирует пак на пути пользователя, приватные/Radmin-адреса и похожие на секреты строки —
  и **останавливает публикацию**, если что-то нашлось (обойти осознанно: `--force`).
- Проверить вручную (те же `tools`): `repo_security_audit.py` — рабочее дерево + вся история git,
  `repo_audit_details.py` — детали по находкам, `privacy_cleanup.py` — разовая очистка личного.

Единственные адреса в репозитории — `26.26.205.227` (ПК владельца в Radmin: на нём держится
быстрая раздача). Это адрес внутри виртуальной сети Radmin, снаружи он недостижим.

## Что где лежит

| Путь | Назначение |
|---|---|
| `bootstrap.txt` | **инструкция загрузки** — стабильный указатель для игроков |
| `_packwiz_run.cmd` | **логика обновления, доставляемая паком** (настройки владельца + фикс-паки): её правки приезжают игрокам сами |
| `_packwiz_update.new` | новая версия стаба; стаб подменяет себя ею последним действием |
| `pack.toml` / `index.toml` | описание пака для packwiz-installer |
| `mods/*.pw.toml` | метафайлы модов (194 — с Modrinth, 21 — свои, хостятся тут же) |
| `mods/*.jar` | только те моды, которых нет на Modrinth (включая самописный `origins_tweaks`) |
| `config/`, `defaultconfigs/` | конфиги модов (без личных: графика, кейбинды, Xaero, EMI) |
| `datapacks/`, `resourcepacks/`, `shaderpacks/` | содержимое пака |
| `dist/` | инстанс-zip и кнопка обновления для игроков |

## Технические детали

- Установщик: `packwiz-installer-bootstrap.jar` (в архиве лежит в `minecraft/`). PrismLauncher
  запускает его как **pre-launch command**: `cmd /c _packwiz_update.cmd` — скрипт читает
  `bootstrap.txt`, выбирает первый доступный источник и запускает установщик.
- Ссылки на файлы этого репозитория строятся от `https://raw.githubusercontent.com/CrystalysGolem/minecraft-pack-1201/main/`
  (константы `GH_USER`/`GH_REPO`/`GH_BRANCH`/`RADMIN_HOST` в `tools/pack_publish.py`).
- Скачивание в скриптах идёт **напрямую, без прокси** (`curl --noproxy "*"`, PowerShell `Proxy=$null`):
  иначе системный прокси ломает и адрес хоста, и GitHub.
- Если понадобится ускорить раздачу — можно включить GitHub Pages и добавить его адрес строкой
  `pack=` в `bootstrap.txt`; перегенерировать пак не требуется.
